# 📋 Firebase 실시간 협업 ToDo 앱 — 제작 프롬프트

이 저장소의 `index.html` 한 파일은 Claude와의 대화로 처음부터 만든 **Firebase Realtime Database 연동 협업 ToDo 앱**입니다. 같은 앱을 다른 프로젝트용으로 새로 만들고 싶다면, 아래 단계를 Claude에게 순서대로 붙여넣으세요.

---

## 🎯 완성된 앱의 전체 기능

| 영역 | 기능 |
|------|------|
| **공통** | Firebase 실시간 동기화, 다크 테마, 동기화 상태 인디케이터, 로딩 오버레이 |
| **헤더** | 프로젝트명, 메타 정보(날짜·장소·인원), D-Day 뱃지, 전체 진행률 바 |
| **네비게이션** | Sticky Nav (To Do / 타임라인 / 연락처) — 부드러운 스크롤 + 자동 active |
| **항목 관리** | 추가·수정(모달)·삭제·완료 토글 |
| **3가지 보기** | 카테고리별 / 우선순위별 / 날짜 임박순 |
| **필터** | 담당기관별 필터 (운영팀/네이버/Upstage/세종대) |
| **완료 항목** | 메인 리스트에서 분리해 하단 접이식 섹션에 별도 표시 |
| **메모(댓글)** | 작성자별 색상, 인라인 수정, 삭제, 항상 펼침 |
| **링크 첨부** | 📎 버튼으로 Google Drive 등 URL 추가, 새 탭에서 열기 |
| **타임라인** | 날짜순 시각화, TODAY 마커, 긴급도 색상, 완료 항목 흐리게 |
| **연락처** | 소속별 카드, 소속 색상 기반, 빈 카드 placeholder |
| **배포** | GitHub Pages, 단일 HTML, 빌드 도구 없음 |

## 🚀 단계별 제작 프롬프트

### STEP 1 — 프로젝트 정보 수집

```
Firebase 실시간 동기화 ToDo 앱을 만들려고 해.
단일 HTML 파일로 동작하고, 여러 명이 동시에 접속해 실시간으로 업데이트를 공유해야 해.
GitHub Pages로 배포할 거야.

앱을 만들기 전에 아래 항목들을 질문 형식으로 먼저 확인해줘.
한 번에 너무 많이 묻지 말고, 연관된 것끼리 2~3개씩 묶어서 물어봐.

확인이 필요한 항목:
1. 프로젝트/행사 이름, D-Day 기준이 될 주요 날짜, 장소 등 헤더 메타 정보
2. 함께 사용할 팀/기관 목록 (이름, 원하는 색상)
3. 업무 카테고리 (이름, 이모지, 색상)
4. 처음부터 넣어둘 초기 할 일 (없으면 샘플로 진행)
5. Firebase 프로젝트가 이미 있는지
```

### STEP 2 — 기본 앱 골격

> STEP 1 답변을 전달한 뒤 이어서 요청

```
위 내용으로 Firebase 실시간 동기화 ToDo 앱을 index.html 단일 파일로 만들어줘.

기술 스택:
- 순수 HTML/CSS/JS (빌드 도구 없음, ESM 방식)
- Firebase Realtime Database SDK v10.12.0 (CDN)
- 폰트: Pretendard (본문), DM Mono (날짜·숫자)
- 다크 테마 (#0f1117 배경)

공통 UI:
- 우하단 고정 동기화 상태 배지 (연결중/저장중/동기화중/오류)
- 첫 로딩 시 스피너 오버레이
- 헤더 우측 D-Day 뱃지 (그라디언트 pill)
- 전체 진행률 바 (완료/전체 카운트 + 퍼센트)

할 일 데이터 구조:
- text, cat, writer, priority(high/mid/low), deadline, agencies[], done, memos, links, order, updatedAt

DB 비어있을 때:
- 초기 데이터 자동 시드 (seedAttempted 플래그로 중복 방지)

Firebase 설정값은 placeholder로 두고, 나중에 교체할게.
```

### STEP 3 — 입력 폼 UI

```
새 항목 추가 폼을 다듬어줘.

- 폼 전체에 파란 테두리 + 은은한 배경으로 다른 영역과 명확히 구분
- 상단에 "✏️ 새 항목 추가" 큰 제목 (font-size 18px, weight 800)
- 각 필드 위에 작은 대문자 레이블
- 필드 순서: 작성자 / 카테고리 / 우선순위 / 업무 기한 / 내용(전체 너비) / 담당기관(전체 너비, 버튼 토글)
- 추가 버튼은 그라디언트, 우측 하단 배치
- Enter 키로도 항목 추가
- 모바일: 4열 → 2열 → 1열로 반응형 전환
```

### STEP 4 — ToDo List 보기 모드

```
To Do List 섹션을 만들어줘.

큰 제목 "To Do List" (font-size 26px, weight 800)와 오른쪽에 뷰 탭 3개:
- 📂 카테고리: 카테고리별 그룹 (전체/카테고리명 필터 표시)
- 🔴 우선순위: 우선/보통/나중 3그룹
- 📅 날짜 임박순: 기한 초과 → 7일 이내 → 한 달 이내 → 이후 → 기한 미설정

뷰 탭 아래 별도 한 줄로:
- 담당기관 필터 (전체/운영팀/네이버/Upstage/세종대)
- 각 버튼은 해당 기관 고유 색상으로 active 표시
- 모든 뷰 모드에서 동시 적용

우선순위·날짜 뷰에서는 각 항목에 카테고리 태그도 함께 표시.
```

### STEP 5 — 항목 카드 + 액션

```
각 할 일 항목 카드를 다음 구조로 만들어줘.

한 줄 배치:
  [완료버튼] [우선순위] [카테고리?] [내용] [담당기관] [기한] | [액션 버튼들]

완료 버튼:
- pill 형태 "✓ 완료"
- 기본 dimmed (반투명 border + 회색 텍스트)
- 완료 시 초록색 하이라이트
- hover 시 미리 초록색으로 변함

우측 액션 버튼 3개:
- 📎 링크 추가
- ✏️ 수정 (모달)
- × 삭제 (confirm)

카드 아래:
- 최종 수정 시각 표시
- 첨부 링크 칩 목록 (있으면)
- 메모 영역 (항상 펼침)

완료 항목: 텍스트 취소선 + 흐릿하게
```

### STEP 6 — 수정 모달

```
✏️ 버튼 클릭 시 수정 모달이 뜨도록 해줘.

- 화면 중앙 오버레이, 바깥 클릭으로 닫힘
- 제목: "✏️ 항목 수정"
- 수정 필드: 내용, 카테고리, 작성자, 우선순위, 기한, 담당기관(버튼 토글)
- 저장 시 updatedAt 자동 갱신
```

### STEP 7 — 메모(댓글) 기능

```
각 항목 아래에 메모(댓글) 영역을 추가해줘.

표시:
- 별도 버튼 없이 항상 펼쳐진 상태
- 3열 그리드: 작성자 | 내용 | 날짜
- 작성자별 고유 색상 (운영팀=흰색, 네이버=초록, Upstage=보라, 세종대=크림슨)

입력창 (항상 표시):
- 통합 박스: 작성자 select | 구분선 | 텍스트 input | 추가 버튼
- Enter로 추가

각 메모 항목에 항상 보이는 액션:
- ✏️ 수정 (인라인 — 클릭 시 해당 줄이 입력창으로 전환, Enter 저장 / Esc 취소)
- × 삭제 (confirm 후 Firebase 제거)

메모 추가·수정·삭제 시 항목 updatedAt 갱신.
```

### STEP 8 — 링크 첨부

```

- 각 칩 옆 × 버튼으로 삭제 가능

저장 위치: tasks/{key}/links 노드
```

### STEP 12 — Sticky 네비게이션

```
헤더 바로 아래에 sticky 네비게이션 바를 추가해줘.

- position: sticky, top: 0
- 반투명 배경 + backdrop-filter blur
- 버튼 3개: 📋 To Do / 📅 타임라인 / 👥 연락처
- 클릭 시 해당 섹션으로 부드러운 스크롤 (smooth behavior)
- 스크롤 중인 섹션이 자동 active 표시 (IntersectionObserver 사용)
- window.scrollTo가 아닌 다른 함수명(navScrollTo)으로 — 네이티브 API와 충돌 회피
```

### STEP 13 — Firebase 연결

> Firebase 콘솔에서 다음 단계 진행

1. [console.firebase.google.com](https://console.firebase.google.com) → "프로젝트 만들기"
2. 이름 입력 → Google Analytics 사용 안함 → 생성
3. 왼쪽 메뉴 **빌드 → Realtime Database → "데이터베이스 만들기"**
4. 위치: **asia-southeast1 (Singapore)** 선택
5. 보안 규칙: **"테스트 모드"** 선택
6. 프로젝트 개요 → **`</>` 웹 앱 추가** → 닉네임 입력 → 등록
7. 표시되는 `firebaseConfig` 블록 전체 복사

```
Firebase 설정이 완료됐어. 아래 설정값을 코드에 넣어줘.

[firebaseConfig 코드 블록 붙여넣기]
```

### STEP 14 — 코드 리뷰 & 배포 점검

```
지금까지 만든 index.html을 꼼꼼하게 점검해줘.

점검 항목:
1. 인코딩: UTF-8, BOM 없음, LF 줄바꿈
2. HTML 메타: DOCTYPE, lang, charset, viewport, 외부 리소스 HTTPS
3. 태그 짝 (div, script, button 등)
4. 중복 id 속성 (같은 요소에 id="" 두 개 있는지)
5. JS 문법: 괄호 매칭, 백틱 짝
6. 모든 onclick 함수가 window.* 로 정의되어 있는지
7. window.scrollTo 같은 네이티브 API 오버라이드 방지
8. 미사용 CSS 클래스/JS 함수
9. Firebase 연동: SDK, 에러 핸들러, 중복 시드 방지
10. 모든 신규 기능이 정상 동작하는지 (Sticky Nav, 완료 섹션, 연락처 등)

문제 발견 시 즉시 수정해서 최종본 만들어줘.
```

### STEP 15 — GitHub Pages 배포

2. 저장소 이름 입력 → 생성
