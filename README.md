# 📋 Firebase 실시간 ToDo 앱 — 빌드 가이드 & 프롬프트

이 저장소의 `index.html`은 Claude와의 대화로 처음부터 만든 **Firebase Realtime Database 연동 협업 ToDo 앱**입니다.  
동일한 앱을 다른 프로젝트에 맞게 새로 만들고 싶다면, 아래 프롬프트를 Claude에게 그대로 붙여넣어 시작하세요.

---

## ✨ 현재 앱의 주요 기능

- **Firebase 실시간 동기화** — 여러 명이 동시에 접속해도 즉시 반영
- **카테고리 / 우선순위 / 날짜 임박순** 3가지 보기 모드
- **완료 여부 필터** — 전체 / 미완 / 완료
- **항목 추가 · 수정 · 삭제**
- **메모(댓글) 기능** — 작성자 + 내용 + 시각, 항상 펼쳐진 상태로 표시
- **담당기관 태그** — 버튼 토글 방식, 기관별 고유 색상
- **완료 버튼** — dimmed 상태로 표시, 클릭 시 초록 하이라이트
- **진행률 바** + D-Day 뱃지
- **GitHub Pages 배포** — 단일 HTML 파일, 빌드 불필요

---

## 🚀 새 프로젝트에서 시작하는 방법

### Step 1 — Claude에게 아래 프롬프트로 시작하기

```
아래 내용을 바탕으로 Firebase 실시간 동기화 ToDo 앱을 만들어줘.
앱을 만들기 전에 먼저 질문을 통해 아래 항목들을 확인해줘.

--- 확인이 필요한 항목들 ---

1. 프로젝트 기본 정보
   - 프로젝트/행사 이름이 뭐야?
   - 주요 날짜나 마감일이 있어? (D-Day 표시에 사용)
   - 장소나 기타 표시할 메타 정보가 있어?

2. 참여 조직/팀
   - 이 ToDo를 함께 사용할 팀/기관이 몇 개야? 이름은?
   - 각 팀마다 원하는 색상이 있어? (없으면 내가 지정할게)

3. 카테고리 구성
   - 업무를 어떻게 묶고 싶어? (예: 기획/개발/디자인/마케팅)
   - 각 카테고리마다 이모지나 색상 지정하고 싶어?

4. 초기 항목
   - 처음부터 넣어둘 할 일 목록이 있어? 있으면 카테고리, 담당, 우선순위랑 같이 알려줘.
   - 없으면 샘플 데이터로 시작할게.

5. 배포 방식
   - GitHub Pages로 배포할 거야?
   - Firebase 프로젝트가 이미 있어, 아니면 새로 만들어야 해?

질문에 답해주면 바로 시작할게!
```

### Step 2 — Firebase 설정

Claude가 코드를 만든 후, Firebase 설정이 필요해요.

**Firebase 콘솔 세팅 순서:**

1. [console.firebase.google.com](https://console.firebase.google.com) 접속
2. **"프로젝트 만들기"** → 이름 입력 → Google Analytics **사용 안함** → 생성
3. 왼쪽 메뉴 **빌드 → Realtime Database → "데이터베이스 만들기"**
4. 위치: **asia-southeast1 (Singapore)** 선택
5. 보안 규칙: **"테스트 모드에서 시작"** 선택
6. 프로젝트 개요 → **`</>` (웹 앱 추가)** → 앱 닉네임 입력 → 등록
7. 표시되는 `firebaseConfig` 코드 블록을 Claude에게 붙여넣기

---

### Step 3 — GitHub Pages 배포

1. [github.com](https://github.com) → **New repository** 생성 (Public)
2. 파일을 **`index.html`** 이름으로 저장 후 업로드
3. **Settings → Pages → Source: Deploy from a branch → main → Save**
4. 1~2분 후 `https://[깃헙아이디].github.io/[저장소이름]` 접속 확인
5. [tinyurl.com](https://tinyurl.com) 등에서 단축 URL 생성 후 팀원 공유

## 🛠️ 커스터마이징 프롬프트 모음

앱이 만들어진 후 아래 프롬프트로 추가 수정을 요청할 수 있어요.

### UI 수정

```
ToDo 리스트의 각 항목 레이아웃을 바꿔줘.
현재: 우선순위 - 내용 - 담당기관 - 기한
변경: [원하는 순서]
```

```
완료 버튼 스타일을 바꿔줘.
[원하는 설명 — 예: 체크박스 형태로, 또는 토글 스위치 형태로]
```

```
색상 테마를 바꿔줘.
배경: [색상코드]
강조색: [색상코드]
다크/라이트 모드: [선택]
```

### 기능 추가

```
항목에 [필드명] 필드를 추가해줘.
입력 방식: [드롭다운 / 텍스트 / 날짜 / 토글 버튼]
표시 위치: [항목 한 줄에 / 메모 위에 / 태그로]
```

```
보기 모드에 [담당기관별 보기]를 추가해줘.
각 기관별로 그룹을 만들고, 기관 색상으로 헤더를 표시해줘.
```

```
항목 정렬 기능을 추가해줘.
정렬 기준: [추가일 / 수정일 / 우선순위 / 기한]
정렬 방향: 오름차순 / 내림차순 선택 가능하게
```

### 데이터 관리

```
Firebase에 있는 기존 데이터를 모두 초기화하고 새 초기 데이터로 시작하고 싶어.
새 초기 항목은:
- [항목1: 카테고리, 내용, 담당, 우선순위]
- [항목2: ...]
이렇게 업데이트해줘.
```

## ⚠️ 운영 시 주의사항

**Firebase 테스트 모드 만료**  
Firebase Realtime Database를 테스트 모드로 시작하면 **30일 후 보안 규칙이 만료**돼서 읽기/쓰기가 막힐 수 있어요. 만료 전에 Firebase 콘솔에서 규칙을 아래처럼 업데이트해주세요.

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

> 소규모 내부 협업용으로는 위 규칙으로 충분해요. 외부 공개가 걱정된다면 Claude에게 인증(Authentication) 추가를 요청하세요.

**초기 데이터 입력**  
앱 첫 접속 시 DB가 비어있으면 자동으로 초기 항목이 입력돼요. 이미 데이터가 있는 상태에서 초기 데이터를 바꿔도 기존 DB는 영향받지 않아요.
