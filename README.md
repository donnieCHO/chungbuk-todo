# 🛠️ Firebase 실시간 협업 ToDo 앱 — 생성 프롬프트

이 문서는 `index.html` 하나로 동작하는 **Firebase 실시간 동기화 협업 ToDo 앱**을 Claude와의 대화로 처음부터 만드는 전체 프롬프트입니다.  
단계별로 순서대로 Claude에게 붙여넣으세요. 각 단계마다 Claude가 질문하거나 결과물을 주면, 다음 단계로 넘어가세요.

## STEP 1 — 프로젝트 기본 정보 수집 (Claude가 먼저 질문하게 하기)

```
Firebase 실시간 동기화 ToDo 앱을 만들려고 해.
단일 HTML 파일로 동작하고, 여러 명이 동시에 접속해서 실시간으로 업데이트를 공유할 수 있어야 해.
GitHub Pages로 배포할 거야.

앱을 만들기 전에 아래 항목들을 질문 형식으로 먼저 확인해줘.
한 번에 너무 많이 묻지 말고, 연관된 것끼리 2~3개씩 묶어서 물어봐.

확인이 필요한 항목:
1. 프로젝트/행사 이름, 주요 날짜(D-Day 기준), 장소 등 헤더에 표시할 메타 정보
2. 함께 사용할 팀/기관 목록 (이름, 원하는 색상)
3. 업무 카테고리 구성 (이름, 이모지, 색상)
4. 처음부터 넣어둘 초기 할 일 목록 (없으면 샘플로 시작)
5. Firebase 프로젝트가 이미 있는지 여부
```

## STEP 2 — 기본 앱 생성

> STEP 1의 답변을 Claude에게 전달한 뒤, 아래 프롬프트로 앱 생성을 요청하세요.

```
위 내용을 바탕으로 Firebase 실시간 동기화 ToDo 앱을 index.html 단일 파일로 만들어줘.

기술 스택:
- 순수 HTML/CSS/JS (빌드 도구 없음)
- Firebase Realtime Database (SDK v10 ESM, CDN)
- 폰트: Pretendard (본문), DM Mono (숫자/날짜)
- 다크 테마 (#0f1117 배경)

기본 기능:
- Firebase 실시간 동기화 (onValue 리스너)
- 실시간 동기화 상태 표시 (우하단 고정 배지: 연결중/저장중/동기화중/오류)
- 로딩 오버레이 (DB 연결 전 스피너 표시)
- D-Day 뱃지 (헤더 우측)
- 전체 진행률 바 (완료 항목 수 / 전체)

할 일 항목 필드:
- 내용 (text)
- 카테고리 (cat)
- 작성자 (writer): [팀 목록]
- 우선순위 (priority): high/mid/low
- 업무 기한 (deadline): 날짜
- 담당기관 (agencies): 복수 선택 가능, 버튼 토글 방식
- 완료 여부 (done)
- 메모 (memos): 하위 컬렉션
- 생성시각 (order), 수정시각 (updatedAt)

DB 비어있을 때: 초기 데이터 자동 입력 (seedAttempted 플래그로 중복 방지)
Firebase 설정값은 나중에 넣을 테니 일단 placeholder로 만들어줘.
```

## STEP 3 — 입력 폼 UI

```
새 항목 추가 폼을 개선해줘.

- 폼 전체를 파란 테두리 + 은은한 배경으로 다른 영역과 명확히 구분
- 폼 상단에 "✏️ 새 항목 추가" 큰 제목 표시 (font-size 18px, font-weight 800)
- 각 입력 필드 위에 레이블 표시 (대문자, 작은 크기)
- 필드 순서: 작성자 / 카테고리 / 우선순위 / 업무 기한 / 내용(전체 너비) / 담당기관(전체 너비)
- 담당기관은 드롭다운이 아니라 버튼 토글 방식 (여러 개 동시 선택 가능)
- 추가 버튼은 그라디언트 배경, 폼 우측 하단 배치
- Enter 키로도 항목 추가 가능
- 반응형: 모바일에서 2열 → 1열로 전환
```

## STEP 4 — ToDo List 보기 모드

```
To Do List 섹션을 개편해줘.

제목:
- "To Do List" 큰 타이틀 (font-size 26px, font-weight 800)
- 제목 옆에 뷰 탭과 완료 필터를 한 줄로 배치

뷰 탭 3개 (pill 버튼 스타일):
- 📂 카테고리: 카테고리별 그룹, 카테고리 필터(전체/카테고리명) 표시
- 🔴 우선순위: 우선/보통/나중 3개 그룹
- 📅 날짜 임박순: 기한 초과 → 7일 이내 → 한 달 이내 → 이후 → 기한 미설정 그룹

완료 필터 탭 3개:
- 전체 / ⏳ 미완 / ✅ 완료
- 뷰 탭과 구분선으로 분리

우선순위·날짜 뷰에서는 카테고리 태그를 항목에 함께 표시
```

## STEP 5 — 항목 카드 레이아웃

```
각 할 일 항목의 레이아웃을 바꿔줘.

완료 버튼:
- 기존 체크박스 대신 "✓ 완료" pill 버튼
- 기본: 반투명 dimmed 상태 (border만 표시, 텍스트 흐릿)
- 완료 시: 초록색 하이라이트
- hover 시: 초록색으로 미리 변함 (클릭 가능하다는 신호)

한 줄 배치:
  완료버튼 | 우선순위태그 | 카테고리태그(뷰에 따라) | 내용 | 담당기관태그들 | 기한

우측 액션 버튼: ✏️ 수정, × 삭제

완료 항목: 텍스트 취소선 + 기한 opacity 감소
```

## STEP 6 — 항목 수정 모달

```
각 항목의 ✏️ 버튼을 누르면 수정 모달이 뜨도록 해줘.

모달 디자인:
- 화면 중앙 오버레이 (배경 어둡게 dimming)
- 모달 바깥 클릭 시 닫힘
- 제목: "✏️ 항목 수정"

수정 가능한 필드:
- 내용, 카테고리, 작성자, 우선순위, 업무 기한, 담당기관(버튼 토글)

저장 시 updatedAt 자동 갱신
```

## STEP 7 — 메모(댓글) 기능

```
각 할 일 항목 아래에 메모(댓글) 기능을 추가해줘.

표시 방식:
- 💬 버튼 없이, 항목 카드 아래에 항상 펼쳐진 상태로 표시
- 메모가 있으면 자동으로 보임

메모 레이아웃 (3열 그리드):
  작성자 | 내용 | 날짜

작성자별 고유 색상 표시 (작성자 이름에 적용)

입력창 (항상 표시):
- 하나의 통합 박스: 작성자 선택 | 구분선 | 내용 입력 | 추가 버튼
- Enter 키로 추가 가능

메모 수정/삭제:
- 각 메모에 ✏️ 수정, × 삭제 버튼 (항상 표시, opacity 숨김 금지)
- 수정은 인라인: 클릭 시 해당 줄이 입력창으로 전환
- Enter 저장, Esc 취소
- 삭제는 confirm 후 Firebase에서 제거

최종 수정 시각:
- 항목 카드에 "최종 수정: YYYY.MM.DD HH:MM" 표시
- 메모 추가/수정/삭제 시도 updatedAt 갱신
```

## STEP 8 — 타임라인

```
페이지 하단(ToDo List 아래)에 타임라인 섹션을 추가해줘.

디자인:
- 섹션 제목: "📅 타임라인" (큰 텍스트)
- 수직 선을 따라 날짜순으로 아이템 배치
- TODAY 마커가 과거/미래를 구분 (점선 + TODAY 레이블)
- 월별 그룹 헤더 표시

아이템 구성 (각 할 일 카드):
- 수직 선에 붙은 점 (색상으로 긴급도 표시)
- 날짜 (MM/DD)
- 카드: 우선순위태그 + 내용 + 완료뱃지
- 카드 하단: 카테고리태그 + 담당기관태그

점/날짜 색상 코딩:
- 빨강: 기한 초과
- 노랑: 7일 이내
- 초록: 오늘
- 파랑: 여유 있음
- 회색: 완료 항목

완료 항목 처리:
- 카드 opacity 38%로 흐릿하게
- 텍스트 취소선
- 점도 흐릿하게

기한 없는 항목: 하단에 별도 "기한 미설정" 영역으로 모아서 표시

renderAll() 호출 시 타임라인도 함께 갱신
```

## STEP 9 — Firebase 연동

> 아래 순서로 Firebase를 설정하고 Claude에게 설정값을 전달하세요.

### 9-1. Firebase 콘솔 세팅

1. [console.firebase.google.com](https://console.firebase.google.com) 접속
2. **"프로젝트 만들기"** → 이름 입력 → Google Analytics **사용 안함** → 생성
3. 왼쪽 **빌드 → Realtime Database → "데이터베이스 만들기"**
4. 위치: **asia-southeast1 (Singapore)** 선택
5. 보안 규칙: **"테스트 모드에서 시작"** 선택
6. 프로젝트 개요 → **`</>` (웹 앱 추가)** → 앱 닉네임 입력 → 등록
7. 표시되는 `firebaseConfig` 블록 전체를 복사

### 9-2. Claude에게 전달

```
Firebase 설정이 완료됐어. 아래 설정값을 코드에 넣어줘.

[firebaseConfig 블록 붙여넣기]
```

## STEP 10 — 코드 리뷰 및 경량화

```
지금까지 만든 index.html을 꼼꼼하게 리뷰해줘.

확인 항목:
1. 배포 점검: 인코딩(UTF-8, BOM 없음), DOCTYPE, viewport, charset, 외부 리소스 HTTPS 여부
2. JS 문법: 괄호/백틱 짝, onclick 함수 정의 여부
3. 사용하지 않는 CSS 변수, 클래스, JS 함수 제거
4. Firebase 연동 로직 검토: onValue 리스너, 에러 핸들러, 초기 데이터 중복 방지
5. 잠재 버그 확인

리뷰 후 수정사항을 적용해서 최종본을 만들어줘.
```

## STEP 11 — GitHub Pages 배포

### 11-1. 저장소 생성 및 업로드

1. [github.com](https://github.com) → **New repository** (Public)
2. 파일을 **`index.html`** 이름으로 저장 후 업로드
3. **Settings → Pages → Source: Deploy from a branch → main → Save**
4. 1~2분 후 `https://[깃헙아이디].github.io/[저장소이름]` 접속 확인

### 11-2. 단축 URL 생성

```
배포된 URL: https://[깃헙아이디].github.io/[저장소이름]
[tinyurl.com](https://tinyurl.com)에서 단축 URL 생성 후 팀원 공유
```

## 커스터마이징 프롬프트 모음

앱 완성 후 추가 변경이 필요할 때 사용하세요.

### 색상 변경

```
담당기관별 태그 색상을 바꿔줘.
[기관명]: [색상코드]
예) 운영팀: #e8ecf4 (흰색), 네이버: #00c73c (초록), Upstage: #8b5cf6 (보라), 세종대: #c3002f (크림슨)
```

### 카테고리 변경

```
카테고리를 아래처럼 바꿔줘.
[카테고리명]: 이모지 [이모지], 색상 [색상코드]
카테고리 중 [이름]은 "추후 업데이트 예정" 안내 배너를 달아줘.
```

### 보기 모드 추가

```
보기 모드에 [담당기관별 보기]를 추가해줘.
각 기관별 그룹, 기관 색상으로 헤더 표시.
```

### Firebase 데이터 초기화

```
Firebase DB를 초기화하고 아래 항목으로 새로 시작하고 싶어.
기존 데이터는 삭제하고 아래 초기 항목을 넣어줘:
- [항목1: 카테고리, 내용, 작성자, 우선순위, 기한]
- [항목2: ...]
```

### Firebase 테스트 모드 만료 대응

Firebase 콘솔 → Realtime Database → 규칙 탭에서 아래로 교체:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

## 전체 기능 요약

| 기능 | 설명 |
|------|------|
| **실시간 동기화** | Firebase onValue로 모든 접속자에게 즉시 반영 |
| **항목 CRUD** | 추가·수정(모달)·삭제·완료 토글 |
| **3가지 보기** | 카테고리별 / 우선순위별 / 날짜 임박순 |
| **완료 필터** | 전체 / 미완 / 완료 탭 전환 |
| **메모** | 덧글 방식, 작성자 색상, 수정·삭제 |
| **타임라인** | 날짜순 시각화, TODAY 마커, 완료 항목 흐릿하게 |
| **진행률 바** | 완료/전체 비율 실시간 표시 |
| **D-Day 뱃지** | 목표일까지 남은 일수 |
| **담당기관 태그** | 버튼 토글, 기관별 고유 색상 |
| **GitHub Pages** | 단일 HTML, 빌드 불필요 |
